## 综合分析：为什么 `HA_evaluation.py` 比 `main.py` 结果差

### 结果对比

| 指标 | HA_evaluation.py | main.py | 差异 |
|------|-----------------|---------|------|
| TC | 0.001 s | 0.001 s | 相同 |
| max_diff | 0.000210 | 0.000280 | HA_evaluation.py 略好 |
| **mean_diff** | **0.000085** | **0.0000277** | **main.py 好 3倍** |

---

### 核心原因：两次独立 RK4 积分 vs 单次数据拟合

```
┌─────────────────────────────────────────────────────────────────┐
│                    数据生成与评估流程                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   CreatData.py (生成 Ground Truth)                              │
│   ┌─────────────────────────────────┐                          │
│   │  JSON (微分方程)                 │                          │
│   │       ↓                         │                          │
│   │  ODESystem + RK4 积分  ──────────┼──→  Ground Truth 数据    │
│   │  (第1次积分，有误差 ε₁)          │                          │
│   └─────────────────────────────────┘                          │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   HA_evaluation.py (评估方式)                                   │
│   ┌─────────────────────────────────┐                          │
│   │  相同 JSON (微分方程)            │                          │
│   │       ↓                         │                          │
│   │  ODESystem + RK4 积分  ──────────┼──→  Simulated 数据       │
│   │  (第2次积分，有误差 ε₂)          │      ↓                   │
│   └─────────────────────────────────┘      │                   │
│                                            ↓                   │
│                              误差 = |ε₁ - ε₂| (两次积分误差叠加) │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   main.py / Dainarx (评估方式)                                  │
│   ┌─────────────────────────────────┐                          │
│   │  Ground Truth 数据               │                          │
│   │       ↓                         │                          │
│   │  DESystem (学习离散映射)  ────────┼──→  Simulated 数据       │
│   │  直接从数据拟合，无积分           │      ↓                   │
│   └─────────────────────────────────┘      │                   │
│                                            ↓                   │
│                              误差 ≈ 拟合残差 (很小)              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

---

### 三个关键原因

#### 1. **两次独立 RK4 积分的误差不可消除**

`HA_evaluation.py` 做的事情：
- 用**相同的微分方程**重新跑一遍 RK4 积分
- 即使方程完全相同，两次积分的**浮点运算轨迹**可能不同
- 特别是在**模式切换点**，检测时刻差 1 个时间步 → 后续轨迹产生偏移

#### 2. **Dainarx 直接从数据学习，绕过了积分**

`main.py` 做的事情：
```python
# DESystem.next() - 直接线性预测
res.append(np.dot(self.config.get_items(self.state, self.input_data, i), self.eq[i]))
```
- 从 Ground Truth 数据中**拟合离散映射**
- 预测公式直接匹配数据的统计特性
- **没有积分误差累积**

#### 3. **误差累积机制不同**

| 方法 | 误差来源 | 累积方式 |
|------|---------|---------|
| HA_evaluation.py | RK4 每步的截断误差 | 10000步 × 小误差 = 累积误差 |
| main.py | 拟合残差 | 每步独立预测，误差不传播 |

---

### 数学直觉

假设真实解为 \(x(t)\)，RK4 每步误差为 \(O(dt^5)\)：

**HA_evaluation.py:**
\[
\text{总误差} \approx N \times O(dt^5) \times 2 = O(dt^4 \cdot T) \times 2
\]
（两次独立积分，误差可能叠加）

**main.py (Dainarx):**
\[
\text{总误差} \approx \text{拟合残差} \approx O(\text{noise in data})
\]
（直接拟合数据，无积分累积）

---

### 结论

> **`HA_evaluation.py` 结果较差的根本原因是：它用微分方程重新积分，产生了与原始数据生成时不同的数值误差轨迹；而 `main.py` (Dainarx) 直接从数据学习离散映射，天然地匹配了数据的统计特性，避免了积分误差累积。**

这也说明：**即使 automaton 完全正确**，`HA_evaluation.py` 的误差也不会为零，这是数值仿真的固有特性。
